# P1 用例执行说明（前置 / 步骤 / 清理）

> 对应代码：`tests/src/specs/*.api.spec.ts`（P1 52 条）
> 对应报告：`tests/P1执行报告.md`
> 数据隔离：每次运行生成 `runId`，每个用例使用独立用户与自建商品；P1 新增 JWT 辅助与契约专项
> 执行方式：`npx playwright test --project=api --grep @p1 --workers=2`

---

## 0. 全局前置与清理（所有用例共用）

### 0.1 前置 fixture / 辅助

| 名称 | 做什么 |
|---|---|
| `runId` | 进程启动时生成一次，格式 `时间戳36进制+随机4位`，用于用户名/商品名去重 |
| `api` | 新建匿名 `APIRequestContext`，不登录 |
| `adminApi` | 用 `admin/admin123` 登录，供管理端接口与商品工厂使用 |
| `freshUser` | 生成唯一用户名 → 注册（密码 `Passw0rd!`）→ 登录；返回 client/username/userId/注册响应 |
| `userApi` | 直接复用 `freshUser.client`，即“当前用例专属用户” |
| `products` | 商品工厂：管理端创建商品并记录 id，测试结束统一删除 |
| `registerFreshUser()` | 在用例内部再注册一个独立用户（越权/隔离用例用），用完手动 `dispose()` |
| `support/jwt.ts`（P1 新增） | `decodeJwt`、`signJwt`、`tamperPayload`、`noneAlgToken`、`detectJwtSecret`；密钥候选含新/旧两套测试密钥，可用 `JWT_SECRET` 覆盖 |

### 0.2 后置清理

| 清理项 | 做法 |
|---|---|
| HTTP 连接 | 每个 client 在 fixture teardown 中 `dispose()` |
| 自建商品 | `products` 记录的 id 逆序删除；已删除的忽略错误 |
| 用户 | 无删除接口，保留 DB；每用例唯一，不影响其他用例 |
| 购物车 / 订单 / 支付单 | 无删除接口，保留 DB；按唯一用户隔离 |
| 支付配置 | `PAY-012`、`PAY-013`、`PAY-025`、`ADM-010` 在 `finally` 中恢复快照；其余用例只传 `outcome` 或只读配置 |
| 商品缓存 | `ADM-008`、`CAT-012` 会读取缓存；`ADM-008` 清缓存不恢复，后续请求自然回源 |
| 过期令牌 | `AUTH-013` 仅在探测到后端 JWT 密钥时执行；探测失败会 `test.skip` |
