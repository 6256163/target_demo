# P0 用例执行说明（前置 / 步骤 / 清理）

> 对应代码：`tests/src/specs/*.api.spec.ts`（P0 44 条）
> 对应报告：`tests/P0执行报告.md`
> 数据隔离：每次运行生成 `runId`，每个用例使用独立用户与自建商品

---

## 0. 全局前置与清理（所有用例共用）

### 0.1 前置 fixture

| fixture | 做什么 |
|---|---|
| `runId` | 进程启动时生成一次，格式 `时间戳36进制+随机4位`，用于用户名/商品名去重 |
| `api` | 新建匿名 `APIRequestContext`，不登录 |
| `adminApi` | 用 `admin/admin123` 登录，供管理端接口与商品工厂使用 |
| `freshUser` | 生成 `u_<runId>_<序号>` 唯一用户名 → 注册（密码 `Passw0rd!`）→ 登录；返回 client/username/userId/注册响应 |
| `userApi` | 直接复用 `freshUser.client`，即“当前用例专属用户” |
| `products` | 商品工厂：调用管理端创建商品，记录 id，测试结束统一删除 |

### 0.2 后置清理

| 清理项 | 做法 |
|---|---|
| HTTP 连接 | 每个 client 在 fixture teardown 中 `dispose()` |
| 自建商品 | `products` 记录的 id 逆序调用 `DELETE /api/admin/products/{id}`；已删除的忽略错误；删除时源码会 evict Redis 缓存 |
| 用户 | 无删除用户接口，保留在 DB；因每用例唯一，不影响其他用例 |
| 购物车 | 无单独清理；随唯一用户隔离，测试结束后保留 |
| 订单/支付单 | 无删除接口，保留在 DB；按唯一用户隔离 |
| 支付配置 | 仅 PAY-004 与遗留 config 用例在 `finally/afterEach` 恢复原值；其余用例只传 `outcome`，不改全局配置 |
| 商品缓存 | CAT-006 会全局清缓存，不恢复；后续请求按需回源 |

## 8. 数据残留说明

- **会删除**：所有通过 `products` 工厂创建的商品；ADM-001 手工登记的商品。
- **不会删除**：测试用户、购物车行、订单、支付单。原因是没有对应用户/订单/支付删除接口；靠“每用例唯一用户 + runId”隔离。
- **会恢复**：PAY-004 与遗留 config 用例修改的全局支付配置。
- **不恢复**：CAT-006 清掉的商品缓存（后续读取会自然回源）。
- 遗留用例“失败率设为 1”创建的商品没有纳入工厂，会留在 DB，建议后续改成 `products.create()`。
