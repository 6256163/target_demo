# target_demo 接口缺陷清单（测试检出）

> 口径：以 `backend/API.md` 为唯一 oracle；实现与文档不一致即登记为缺陷。`API.md` 未定义的行为单独归入 §5「基线/待确认」，不计入缺陷数。
> 证据来源：`P0执行报告.md`、`P1执行报告.md`、`P2执行报告.md`；全部缺陷均保留红色用例，未使用 `test.fail()` 隐藏。
> 统计：**P0 5 条 + P1 20 组 + P2 10 组**，按根因归并为 **21 个缺陷**（DEF-01 ~ DEF-21）。

---

## 1. 严重（S1：资金/库存/越权）

### DEF-01 支付单水平越权（可读他人支付单并退款）

- 用例：PAY-016、SEC-001、SEC-008
- 证据：B 用户用 A 的 `tradeNo` 调用 `GET /api/payments/{tradeNo}` → 200/0 返回完整支付单；`GET /api/payments?orderNo=...` → 200/0；`POST /api/payments/{tradeNo}/refund` → 200/0，支付单变 `REFUNDED`、A 的订单被置 `CANCELLED`。
- 根因：`PaymentService.get/listByOrder/refund` 均未校验 `payment.userId == CurrentUser.id()`。
- 影响：任意登录用户可枚举/退款他人支付单，直接造成资金与订单状态损失。
- 期望：403/40300，且不得返回支付单数据。

### DEF-02 取消与支付竞态：取消返回成功但订单最终 PAID

- 用例：ORD-019、CON-005
- 证据：并发调用 `POST /orders/{no}/cancel` 与 `POST /payments` 后，取消返回 200/0，但订单最终状态为 `PAID`，支付单 `SUCCESS`。
- 根因：`cancel` 与 `pay` 均无行锁/条件更新；`markPaid` 对 `CANCELLED` 不拒绝，直接覆盖为 `PAID`。
- 影响：用户被告知取消成功，实际仍被扣款。
- 期望：终态唯一；订单已取消时支付必须失败，或支付成功后取消必须 40904。

### DEF-03 超时重付不扣库存 + 退款再回滚 → 库存虚增

- 用例：ORD-008（P0）、PAY-021、DAT-003
- 证据：
  - 下单 2 件：库存 10→8；支付 TIMEOUT 回滚到 10；
  - 重新支付 SUCCESS 后库存仍为 **10（应为 8）**；
  - 退款后库存变为 **11/12（应为 10）**。
- 根因：支付成功路径不消耗库存（库存只在下单时扣），但失败/退款路径按“已扣减”假设执行 `restoreStock`。
- 影响：库存守恒被破坏，长期运行会虚增库存并导致超卖。
- 期望：支付成功不再回滚的库存语义需统一：要么成功时扣减、失败/退款时回滚；要么失败/退款仅在确实扣减时回滚。

## 2. 高（S2：核心功能/安全/幂等）

### DEF-04 idempotencyKey 未实现，重试支付产生多张支付单

- 用例：PAY-019、CON-003
- 证据：
  - 支付 TIMEOUT 后用**同一** `idempotencyKey` 重试 → 新建支付单（`tradeNo` 不同），列表 2 张；
  - P2 首轮 5 并发同 key → **5 张支付单，全部 SUCCESS**（并发窗口内各自插入）。
- 根因：`PaymentService.pay` 未读取/存储 `idempotencyKey`；“PAYING 时复用 PROCESSING 单”无法覆盖 `PAY_FAILED` 重试与并发读 `PENDING_PAYMENT`。
- 期望：同 key 至多 1 张支付单、1 条 SUCCESS。

### DEF-05 refreshToken 与 accessToken 可互换

- 用例：AUTH-014、SEC-003
- 证据：refreshToken 访问 `/api/cart`、`/api/auth/me` → 200/0；accessToken 调用 `/api/auth/refresh` → 200/0 并换发新令牌。
- 根因：token 内含 `typ` claim，但过滤链与刷新接口均未校验 `typ`。
- 影响：refreshToken 泄露即可直接访问业务接口，令牌分层失效。

### DEF-06 管理端非法发货/收货静默成功

- 用例：ORD-015、ADM-009
- 证据：未支付订单发货/确认收货、`DELIVERED` 后重复发货、重复收货、已取消订单发货 → 均 **200/0**，状态不变。
- 根因：`markShipped/markDelivered` 对不满足前置状态的分支直接 `return`。
- 期望：409/40904。

### DEF-07 并发注册/并发加购触发唯一键 500，并泄露 SQL

- 用例：AUTH-016、CART-013
- 证据：
  - 8 并发注册同一用户名：1 成功，其余 **500/50000**，message 含 `Duplicate entry ... for key 'users.uk_users_username'` 与完整 `insert into users ...`；
  - 10 并发加购同一商品：多个 **500/50000**（`cart_items.uk_cart_user_product`），最终数量仅 **3（应 10）**，存在丢失更新。
- 根因：先查后插无锁/无重试，`DataIntegrityViolationException` 未映射为 40901/幂等累加。
- 期望：其余注册 409/40901；加购单行累加、数量=Σ成功请求，不 500、不泄露 SQL。

### DEF-08 支付配置越界值被接受

- 用例：ADM-010
- 证据：`failureRate=1.5/-0.1`、`timeoutRate=1.5`、`minDelayMs=-1` 均 **200/0**；仅 `minDelayMs > maxDelayMs` 被服务层拒绝。
- 根因：`PaymentConfigRequest` 有校验注解，`AdminPaymentController` 入参缺 `@Valid`。
- 影响：可将失败率/超时率配到非法区间，破坏支付概率语义。

### DEF-09 商品 status 未按枚举校验

- 用例：ADM-015
- 证据：新建 `status=BAD`、`status=on_sale`、更新 `status=INVALID` 均 **200/0** 并落库。
- 根因：`ProductUpsertRequest.status` 为 String，无枚举校验；OpenAPI 也无 enum。
- 影响：非法状态使商品在用户端不可预期（既非 ON_SALE 也非 OFF_SALE）。

### DEF-10 支付/回调入参缺少校验，类型错误 500

- 用例：PAY-011、PAY-012
- 证据：
  - 缺少/空 `orderNo` → **404/40402**（应 400/40000）；
  - 非法 `payType`/`outcome` → **500/50000**；
  - 回调缺少/非法 `status` → **500/50000**；
  - `callbackId` 500 字符 → **500/50000**。
- 根因：`PayRequest` 无 `@Valid`；回调 `@RequestParam PaymentStatus` 的类型转换异常未映射；`callbackId` 无长度约束/列超长。

### DEF-11 购物车累计/修改数量可突破库存，缺 quantity 500

- 用例：CART-007、CART-008、CART-014
- 证据：
  - 已有 1 件、库存 10，再加 10 件 → 200/0，数量 11；
  - 修改为 11（库存 10）→ 200/0；修改为 -1 → 200/0 且条目被删除；缺少 `quantity` → **500/50000**；
  - 加购 `productId="abc"`/`quantity="x"`/int 溢出 → **500/50000**；`quantity=1.5` → 200/0 静默截断。
- 根因：`CartService.add/updateQuantity` 只校验单次/不校验库存上限与正数；`CartItemRequest` 无 `@Valid`、无类型异常映射。

### DEF-12 LIKE 通配符未转义，`%`/`_` 返回全量

- 用例：CAT-008、SEC-004
- 证据：`keyword=%` → `total=204/206`（全量）；`keyword=_` 同样命中全量；注入串 `' OR 1=1--` 返回 0（无注入）。
- 根因：直接拼接 `like %keyword%`，未转义 `%`/`_`。
- 影响：数据枚举/性能放大；`%` 输入可拖垮列表页。

### DEF-13 Actuator 端点过度暴露

- 用例：SEC-010
- 证据：匿名访问 `/actuator/metrics`、`/actuator/prometheus`、`/actuator/info` → **200**；`/actuator/env`、`/actuator/beans` 等 → 500（未暴露但同样未鉴权兜底）。
- 根因：`management.endpoints.web.exposure.include=health,info,metrics,prometheus,httpexchanges` + `SecurityConfig` 的 `anyRequest().permitAll()`。
- 期望：仅 `/actuator/health/**` 匿名，其余 401/403/404。

## 3. 中（S3：契约/错误码/异常分支）

### DEF-14 认证失败路径返回 500（未登录/无效/过期 token 访问 `/api/auth/me`）

- 用例：AUTH-004（P0）、AUTH-012、AUTH-013
- 证据：匿名、篡改签名、过期 accessToken 访问 `/api/auth/me` → **500/50000**；访问 `/api/cart`、`/api/admin/**` 则正确 401。
- 根因：`/api/auth/**` permitAll + `me()` 内 `CurrentUser` 无用户时抛异常。
- 期望：401/40100。

### DEF-15 订单状态不允许支付的错误码口径错误

- 用例：ORD-014、PAY-009（P0）
- 证据：已取消/已支付订单再支付 → **409/40906**；API.md §3.6 要求 `40904`。
- 影响：客户端按文档无法区分“订单状态不允许”与“支付单状态不允许”。

### DEF-16 空购物车相关错误码缺失（40905）

- 用例：CART-009、ORD-023、CTR-003
- 证据：空购物车清空 → 200/0（应 409/40905）；`fromCart=true` 空购物车下单 → 400/40000（应 409/40905）。
- 影响：文档 §1.4 的 40905 无自然触发路径。

### DEF-17 分页/筛选参数类型错误返回 500

- 用例：CAT-007、CAT-009、SEC-004、ORD-004（P0）
- 证据：
  - `size=0/-1` → **500/50000**（应 400/40000）；
  - `categoryId=abc` / `1 OR 1=1` → **500/50000**；
  - `status=BAD`（订单列表）→ **500/50000**。
- 根因：`MethodArgumentTypeMismatchException`/`IllegalArgumentException` 未映射到 40000。

### DEF-18 成功响应缺少 traceId

- 用例：CTR-001、CTR-008
- 证据：所有成功响应无 `traceId`；业务错误有 16 位 traceId，安全 401/403 无。
- 根因：`ApiResponse.ok()` 未设置 traceId；仅 `GlobalExceptionHandler` 设置。
- 期望：按 API.md §1.2 统一信封补齐。

### DEF-19 401/403 中文 message 乱码

- 用例：CTR-003
- 证据：`message` 为 `?????????` / `?????`，`Content-Type: application/json;charset=ISO-8859-1`。
- 根因：`SecurityConfig` 直写响应未设置 UTF-8。

### DEF-20 清商品缓存为空实现

- 用例：CAT-006（P0）、ADM-008
- 证据：接口返回 `true`，但清缓存后详情仍 `cached=true`，Redis key 未删除。
- 影响：管理端无法强制刷新缓存，改价/删除后的缓存治理失效（更新/删除本身会 evict，仅手动清缓存无效）。

### DEF-21 超长收货信息导致 500

- 用例：ORD-009
- 证据：`receiverName` 300 字、`phone` 100 位、`address` 600 字、`remark` 300 字 → **500/50000**（数据库列超长异常未映射）。
- 期望：4xx 或截断，不应 500。

## 5. API.md 未定义：已固定的实现基线（非缺陷，建议产品确认）

| 项 | 当前实现 | 用例 |
|---|---|---|
| OFF_SALE 商品可见性 | 用户端列表/详情不过滤下架商品 | CAT-011、ADM-007 |
| 购物车快照价 vs 下单取价 | 购物车按 `snapshotPrice`，fromCart 下单按商品最新价（会出现购物车 20 / 订单 40） | CART-011、DAT-005 |
| 管理员读他人订单 | `assertOwnership` 对 ADMIN 放行 | ORD-012 |
| 自动关单 | 只置 `CANCELLED` 并回滚库存，不生成/关闭支付单（`CLOSED` 未实现） | ORD-021（默认环境跳过） |
| 重复删除/删除不存在条目 | 200/0 幂等 | CART-009 |
| 分页上限 | `size` 收敛到 200；`page<0` 钳制为 0 | CAT-007 |
| 同商品多行下单 | 不合并，按行建明细、按行扣库存 | ORD-010 |
| 空值缓存 | 不存在商品 30 次请求稳定 404，P95=7ms（缓存穿透受控） | CAT-013 |
| CORS | `allowedOriginPatterns=*` + `allowCredentials=true`（文档明示） | SEC-009 |

> 上述项在用例中均有 `test.info().annotations` 记录；若产品确认应视为缺陷，可直接将对应断言改为文档期望值。
